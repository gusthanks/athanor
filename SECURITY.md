# Security

Do not report secrets, private customer data, or vulnerable production details
in a public issue. Share a minimal, synthetic reproduction instead.

Athanor must never:

- print credential values;
- commit `.env` files or secret-bearing configuration;
- treat a private Git repository as a secret manager;
- upload project content without explicit authorization;
- apply an organization plan that was not approved;
- delete source files as part of normal organization;
- bypass a human gate for spending, publishing, legal commitments, production
  changes, or personal data.

Security reports can be routed privately once a maintainer contact is published.
Until then, do not disclose an exploitable issue publicly; retain the report and
contact the repository owner through their verified GitHub profile.
