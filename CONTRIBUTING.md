# Contributing

Keep Athanor safe, understandable, and portable.

1. Open an issue describing the user problem and the intended behavior.
2. Keep each skill focused and use progressive disclosure.
3. Do not add real company data, credentials, personal information, or private
   examples.
4. Default filesystem and external-service workflows to read-only, dry-run, or
   draft behavior.
5. Add or update tests for deterministic scripts.
6. Run every skill validator and the plugin validator before submitting.
7. Use `YYYY-MM-DD` for dates.

Examples must be synthetic. A sanitized example must be newly authored; deleting
private values from a copied business file is not sufficient if its history or
structure can still reveal confidential information.
