# Scenarios

## A new business with four founders

Invoke `$athanor`. The system inventories existing material, asks only for
decisions it cannot discover, identifies missing ownership and sources of truth,
then proposes a minimum operating system. It does not demand a mature design
system, CRM, legal library, and automation stack on day one. Gaps are separated
into now, next, and later.

## A flat creative folder

Invoke `$athanor-organize`. The system inventories filenames and metadata,
extracts text or previews only when needed, proposes a taxonomy, and writes an
organization manifest. Files remain in place until the manifest is reviewed.
The apply script runs in dry-run mode by default and requires an explicit
backup acknowledgement.

## A mature codebase

Invoke `$athanor-audit`. Generated directories, dependencies, caches, and
secrets are excluded from content inspection. Existing architecture and test
contracts are treated as evidence. The system adds business governance only
when useful; it does not reorganize source code to match a generic business
template.

## A 20 GB business workspace

Invoke `$athanor-chronicle`. The system explains the difference between Git,
GitHub, Git LFS, asset storage, and backup. It recommends versioning small
authoritative text, code, configuration, and templates while keeping media,
scans, caches, and sensitive binaries in appropriate storage.

## Social publishing automation

Invoke `$athanor-integrate`. The system starts from the outcome and compares
manual assistance, a connector, no-code automation, a direct API, and MCP. It
verifies current official documentation before giving provider-specific setup
steps and never stores tokens in project documents.
