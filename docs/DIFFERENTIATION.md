# Positioning and Differentiation

Athanor sits between a one-off prompt, a folder template, an agent roster, and a
heavy enterprise operating framework.

## Distinctive choices

- **Workspace-first:** it discovers the real project before prescribing a
  structure.
- **Starts at zero, respects maturity:** it can teach Git to a beginner without
  flattening an established engineering repository into a generic template.
- **One product, focused modules:** routing, audit, organization, preservation,
  agents, integrations, and memory remain independently testable.
- **Modes do not weaken gates:** autonomy preference and business authority are
  separate controls.
- **Plan before mutation:** file organization separates probabilistic
  classification from deterministic execution.
- **Preservation is broader than Git:** repository history, LFS, asset storage,
  backup, and secret management are treated as different layers.
- **Capability-aware:** it recommends APIs, MCPs, connectors, and automation
  only after understanding the outcome and missing capability.
- **Memory has provenance:** canonical project truth outranks summaries and
  agent-private learning.
- **Mystical vocabulary, plain artifacts:** the experience can feel ritualistic
  without obscuring files, logs, or governance from humans and other agents.

## What Athanor is not

- a bundled autonomous company;
- a replacement for legal, financial, privacy, or security professionals;
- a secret manager or backup service;
- a universal folder taxonomy;
- an excuse to create many decorative agents;
- a provider-specific automation bundle.

## Public-project boundary

The repository contains only reusable method, synthetic templates, and local
utilities. Brand knowledge, customer data, project-specific agent memories,
credentials, and internal examples belong in the adopting project, not here.
