# Memory and Drift

## Memory hierarchy

1. current live evidence;
2. canonical project artifact;
3. recorded human decision;
4. project operating-system summary;
5. agent role spec;
6. agent-private memory.

If private memory conflicts with a stronger source, correct the memory.

## What belongs in memory

- verified recurring pattern;
- tool limitation personally tested;
- stable user preference stated directly;
- hard-to-find path with evidence;
- lesson from an incident that changes future behavior.

## What does not

- token, password, key, or personal secret;
- guess or estimate presented as fact;
- current task status;
- product or price fact owned elsewhere;
- narrative activity log;
- copied external documentation.

## Drift checks

- paths that no longer exist;
- duplicate task lists;
- two editable copies of the same fact;
- tool capability without verification date;
- agent ownership that no longer matches work;
- stale integration authorization;
- generated file edited by hand;
- summary that contradicts code or a canonical document.
